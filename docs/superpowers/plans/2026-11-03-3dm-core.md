# 3DM Web App — Kickoff Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the kickoff milestone of the 1156 3DM app: allowlisted Google login, seasons and groups, all five 3DM stages as live collaborative pages, pipeline home with presence, inline AI items from the game manual (browser-held key), and full history.

**Architecture:** Static React SPA on Firebase Hosting; no server of our own. Firestore holds seasons, step state, generic items and an append-only history; Realtime Database holds presence only. The 3DM structure is a **static template** (`src/threedm/template.ts`) of steps → item kinds → columns, so one generic table editor renders most steps; three special views (priority board, decision matrix, CAD budget) cover the rest. AI calls go from the browser to Anthropic/OpenAI with a key kept in `localStorage`.

**Tech Stack:** Vite + React 19 + TypeScript, react-router, Tailwind CSS, Firebase JS SDK (auth, firestore, database), zod, pdf-lib, `@anthropic-ai/sdk`, `openai`, Vitest + Testing Library, `@firebase/rules-unit-testing` + Firebase emulators (`firebase-tools` as devDependency).

**Spec:** `docs/superpowers/specs/2026-11-03-3dm-webapp-design.md`

## Global Constraints

- 1156 only: access = Google sign-in **and** email present in `members` with role `admin` or `member`.
- UI copy in **Portuguese**; game terms stay in English as in the manual (HUB, FUEL, TRENCH…).
- Firebase **Spark** plan: no Firebase Storage, no Cloud Functions. Images compressed client-side into Firestore (each doc < 1 MB; target image ≤ 200 KB) or stored as external links.
- Saves per item/field on blur, never per keystroke. Each save = item write + one history event in the same batch.
- Presence lives in Realtime Database, not Firestore.
- API key only in `localStorage` (`3dm.ai.key.anthropic`, `3dm.ai.key.openai`); never written to Firestore, never logged.
- Default AI: Anthropic `claude-sonnet-5-5`; OpenAI alternative; provider + model stored in `config/app`.
- AI output is never silently a decision: items keep `origin` (`human` | `ai` | `ai-accepted` | `ai-edited`); AI never overwrites a non-`ai` item.
- No stage gating: every step is always editable while the season is active.
- Archived seasons are read-only (enforced in rules).
- Commits: author is the user's git identity; **no `Co-Authored-By: Claude` trailer**.
- The xlsx/pdf source files are git-ignored and never committed.

## Review Focus

1. **Malformed or truncated AI output** — a model returning invalid JSON or schema-violating data must write nothing and show a clear Portuguese error. → test in Task 10 (`rejects invalid extraction without writing`).
2. **Re-running manual setup** — must add only new AI items, never duplicate existing ones or touch human/accepted items. → test in Task 11 (`mergeExtraction skips existing keys and human items`).
3. **Manual larger than the provider's page limit** (FRC manuals ~130+ pages) — must be split and merged, not fail. → test in Task 11 (`splitPdf chunks at 90 pages`).
4. **Removed from allowlist mid-session / archived season** — writes must be denied by rules, not just hidden in UI. → tests in Task 3.
5. **Missing or invalid API key** (401) — AI buttons must say "configure uma chave" / "chave inválida", not crash. → test in Task 10 (`maps 401 to invalid-key error`).

## Firestore model (used by all tasks)

```ts
// src/threedm/types.ts
type Role = 'admin' | 'member';
interface Member { email: string; role: Role; displayName?: string }            // members/{email}
interface AppConfig { aiProvider: 'anthropic' | 'openai'; model: string }         // config/app
interface Season { id: string; name: string; year: number; status: 'active' | 'archived';
  model?: SeasonExtraction; createdAt: number }                                   // seasons/{sid}
interface Group { id: string; name: string; memberEmails: string[] }             // seasons/{sid}/groups/{gid}
type StepStatus = 'nao_iniciado' | 'em_andamento' | 'em_revisao' | 'concluido';
interface StepState { stepId: string; groupId?: string; deadline?: string /*YYYY-MM-DD*/;
  status: StepStatus; conclusion: string; closedBy?: string; closedAt?: number } // seasons/{sid}/steps/{stepId}
type Origin = 'human' | 'ai' | 'ai-accepted' | 'ai-edited';
interface Item { id: string; stepId: string; kind: string; data: Record<string, unknown>;
  origin: Origin; state: 'active' | 'rejected'; order: number; aiKey?: string; citation?: string;
  createdBy: string; updatedBy: string; updatedAt: number }                       // seasons/{sid}/items/{id}
type HistoryAction = 'create' | 'update' | 'accept' | 'reject' | 'delete' | 'step-update' | 'close' | 'reopen';
type NewItem = { stepId: string; kind: string; data: Record<string, unknown>; origin?: Origin; aiKey?: string; citation?: string };
interface HistoryEvent { at: number; by: string; stepId: string; itemId?: string; action: HistoryAction;
  before?: unknown; after?: unknown; reason?: string }                            // seasons/{sid}/history/{id}
```

`aiKey` is a stable dedupe key the AI assigns (e.g. `rule:G403`, `skill:coletar-fuel-chao`).

**Files:**

**Interfaces:**
- Produces:
```ts
nextOrigin(origin: Origin, action: 'accept' | 'edit'): Origin
// ai+accept→ai-accepted; ai+edit→ai-edited; ai-accepted+edit→ai-edited; human stays human
scoreMatrix(input: { archetypes: string[]; priorities: {id: string; bucket: 'Precisamos'|'Queremos'}[];
  coverage: {archetypeId: string; priorityId: string; atende: boolean}[];
  attributes: {atributo: string; peso: number}[]; scores: {archetypeId: string; attribute: string; nota: number}[] })
  : Record<string, { coveragePct: number; weighted: number; finalPct: number; missingNeeds: string[] }>
cadBudget(rows: {peso_kg?: number}[], max: number): { used: number; remaining: number }
stepSummary(items: Item[]): { total: number; aiPending: number; rejected: number }
```
- `scoreMatrix` algorithm: `coveragePct` = covered / total Precisamos+Queremos; `weighted` = Σ(peso × nota) / (Σpeso × 5); `finalPct` = round(100 × (coveragePct + weighted) / 2); any uncovered Precisamos listed in `missingNeeds`. Notas are 0–5. (Builder note: this reproduces the sheet's "Percentual atingido" + "Nota para atributos" blend; show both parts in UI so the team can judge.)
